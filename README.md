# Computer code engineering services section

Owns services whose primary subject is computer code, including programming
languages and the development systems that produce, examine, version, and
deliver code.

The content-address source-domain audit is owned by the independent Data
library `@red-cup-engineering/semiotic-content-address/audit`, mounted at
`computer-data-engineering-services-section/lib/semiotic-content-address`.
Computer Code continues to own general-purpose source introspection and
package/repository normalization, not a duplicate content-specific scanner.

## Source-owned typed operation invocation

Code `./typed-operation-invoke` now owns the one original pure
request→admitted operation→typed result/refusal dispatch. It was moved
from JSNode rather than duplicated. Its operation table rejects inherited
prototype methods and unknown codecs; thrown business exceptions do not
leak private exception contents; an unencodable output yields a typed refusal.
The JSNode text-tier consumer uses this Code export and retains only its
text-specific namespace rule. JSNode's former `./invoke-typed-operation`
export and local implementation are retired in its 0.4.0 source edition.
Existing exact V1 message IDs remain in Code `./typed-operation-message`.
Full registry release/installation and migrating any independently held
old JSNode clients remain separate receiving obligations.

## Bounded exact source construction

`./exact-source-edit-operation` exposes the object-input body
`applyExactSourceEditOperation`, its closed `inputSchema`/`outputSchema`, and
the original operation-family `effects` shape. It delegates once to the
unchanged `./exact-source-edits` primitive with mandatory preimage/span guards,
bounded UTF-8 bytes, scalar-aligned UTF-16 offsets and NFC-stable input/output.
The [source specification](content/text/documents/articles/specifications/exact-source-edit-operation.md)
defines its deliberately narrower domain. It is not itself an admitted
Operation: the existing higher operation owner captures the exported body
through JSNode and composes the original descriptor, without making Code
depend upward on Relating or creating another registry.

Its child smart-contract-audit-engineering-services-section audits Solidity codebases and admits only findings proven by a runnable proof-of-concept on a local fork.
