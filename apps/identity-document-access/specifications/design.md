# Behavior and architecture

This is a Code application consuming Data. It lives beside the existing Code applications; no networking transport or autonomous external actuator is added. The personal service owns the case, public-source register and a linked analysis model. The engine accepts these three values and returns an assessment. Source snapshots remain with the existing consumer register, not in a new evidence database. There is no hidden global customer state.

Input schema validation uses the existing JSON Schema service. Public claims are admitted as native attributed source statements, whose content address identifies the statement rather than proving its truth. An optional statementId pins the exact native statement selected in a Science study. The engine reconstructs that address from the supplied assertion and source metadata; a mismatch blocks the guard without erasing unrelated observed facts. The study owner retains the actual native carrier for independent readmission. Observations refer by JSON Pointer into the existing personal case. Positive and negative observations survive independently under the existing FOUR algebra. Receipt nodes additionally require an observed receiver outcome matching that node's declared receipt contract; case-report observations cannot satisfy them.

An acquisition step has AND inputs and source-bound guards. Several steps may produce the same node, providing alternatives. Current executability is computed only from held observations and current guards. A separate finite closure describes conditional future reachability; receiver decisions never manufacture a positive outcome. A recursive dependency walk returns circular explanations, while unseeded cycles remain unreachable. Research tasks reference missing nodes or guards and expose falsification/stopping criteria. They are preparation instructions, not scheduled jobs or authorization to contact anyone.

A variance matrix reads authored arguments and exhibits against a supplied obligation list. It checks available exhibits and issuer provenance, attempted recovery and unresolved objections. It reports missing support and never declares legal sufficiency. A scenario assumes explicitly named nodes solely for a labeled hypothetical report. Source comparison returns dependent claim and action IDs; source freshness is checked against an explicit assessment date and per-source review interval. Local snapshot hashes are checked by the CLI before assessment.

The analysis CLI supports assess, packet, scenario, source-impact and observe. Observe returns a case-bound model-update proposal using an existing case witness; it does not silently alter either input. Analysis writes only to stdout; the personal caller may save a review artifact. The separate init command creates a new private case as described below. No command sends mail, pays a fee, files an application, acquires records, or schedules a follow-up. Those actions require their actual service actuator and receipt. This is an operational local reasoning tool, not a deployed multi-user service. Tests cover the concrete false inferences that caused the failed handling of Morgan's case, plus independent synthetic clients.

The `init` command consumes an Operations-owned four-record template rather than cloning a customer's case. Its small manifest names case, model, source-register and service-parameter files. Filenames are distinct basenames, and every input is a regular file. Case and model must carry the exact unbound case-ID sentinel; client label is unbound; facts, attempts, inventories, routes and observations start empty, with no inherited grants or filing/spending authority. Exact scalar sentinels bind case ID and date. The service parameters must refer to the supplied filenames. The existing assessment validates the composed result before exclusive destination creation. Directory creation refuses an existing destination, including a symlink; file creation is exclusive and private. A failed write removes only the files this invocation created and attempts to remove its otherwise-empty directory. No recursive deletion or existing-client update occurs. The client owner supplies the destination under their own private custody. Template contents still require editorial review; the initializer cannot identify arbitrary sensitive prose supplied by an operator.

The optional `evidenceManifestPath` in consumer parameters binds the existing private acquisition manifest. Its case ID and source IDs are explicit; files are basenames relative to that manifest. The audit uses ordinary-file checks, no-follow file opens, a streaming native SHA-256 and before/after file metadata. The JSON Schema provider admits this application profile. Missing or malformed manifests yield an unavailable audit; they do not erase unrelated case observations. Audit results omit filenames, paths and contents. Models name required `artifactSourceIds` on particular nodes. A matching, problem-free file audit is an additional usability condition for those nodes; FOUR continues to describe the attributed observations. The CLI performs real I/O. The pure assessment API consumes its caller-supplied audit and cannot authenticate a forged caller claim; it does reject an audit bound to another case. No audit confers document admissibility or contact authority.
