# Behavior and architecture

This is a Code application consuming Data. It lives beside the existing Code applications; no networking transport or autonomous external actuator is added. The personal service owns the case, public-source register and a linked analysis model. The engine accepts these three values and returns an assessment. Source snapshots remain with the existing consumer register, not in a new evidence database. There is no hidden global customer state.

Input schema validation uses the existing JSON Schema service. Public claims are admitted as native attributed source statements, whose content address identifies the statement rather than proving its truth. An optional statementId pins the exact native statement selected in a Science study. The engine reconstructs that address from the supplied assertion and source metadata; a mismatch blocks the guard without erasing unrelated observed facts. The study owner retains the actual native carrier for independent readmission. Observations refer by JSON Pointer into the existing personal case. Positive and negative observations survive independently under the existing FOUR algebra. Receipt nodes additionally require an observed receiver outcome matching that node's declared receipt contract; case-report observations cannot satisfy them.

An acquisition step has AND inputs and source-bound guards. Several steps may produce the same node, providing alternatives. Current executability is computed only from held observations and current guards. A separate finite closure describes conditional future reachability; receiver decisions never manufacture a positive outcome. A recursive dependency walk returns circular explanations, while unseeded cycles remain unreachable. Research tasks reference missing nodes or guards and expose falsification/stopping criteria. They are preparation instructions, not scheduled jobs or authorization to contact anyone.

A variance matrix reads authored arguments and exhibits against a supplied obligation list. It checks available exhibits and issuer provenance, attempted recovery and unresolved objections. It reports missing support and never declares legal sufficiency. A scenario assumes explicitly named nodes solely for a labeled hypothetical report. Source comparison returns dependent claim and action IDs; source freshness is checked against an explicit assessment date and per-source review interval. Local snapshot hashes are checked by the CLI before assessment.

The CLI supports assess, packet, scenario, source-impact and observe. Observe returns a case-bound model-update proposal using an existing case witness; it does not silently alter either input. It writes only to stdout; the personal caller may save a review artifact. No command sends mail, pays a fee, files an application, acquires records, or schedules a follow-up. Those actions require their actual service actuator and receipt. This is an operational local reasoning tool, not a deployed multi-user service. Tests cover the concrete false inferences that caused the failed handling of Morgan's case, plus an independent synthetic client.
