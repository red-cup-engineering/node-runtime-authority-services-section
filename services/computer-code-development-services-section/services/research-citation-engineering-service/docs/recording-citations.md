# Recording citations

A research note is self-contained: it declares what it cites in its own frontmatter, with full citation metadata.
The body invokes those citations with Pandoc-style `[@key]` at the precise point each work is used.

## The `references:` block

```yaml
---
kind: theorem
status: proved
references:
  - key: arnold1995remarks
    type: article
    authors: ["V. I. Arnold"]
    year: 1995
    title: "Remarks on eigenvalues and eigenvectors of Hermitian matrices, berry phase, adiabatic connections and quantum Hall effect"
    journal: "Selecta Mathematica New Series"
    volume: 1
    number: 1
    pages: "1–19"
  - key: bik2020euclidean
    type: article
    authors: ["Jan Bik", "Jan Draisma"]
    year: 2020
    title: "An Euclidean distance degree formula for ..."
    journal: "Linear Algebra and its Applications"
    eprint: "1906.07089"
    eprinttype: arxiv
---

# A theorem about ...

The codimension formula refines work in [@arnold1995remarks]. It uses the
distance-degree machinery of [@bik2020euclidean].
```

This is the whole model.
Every citation in the body must have a matching entry in this note's `references:` block, with full metadata.
The bib for the domain is generated by walking every note's `references:` and merging by `key`.

## Citing in the body

Pandoc citation syntax.
The validator enforces that every body cite appears in the note's `references:`.

| Syntax            | Renders as                    |
|-------------------|-------------------------------|
| `[@key]`          | (Author Year)                 |
| `[@key, p. 42]`   | (Author Year, p. 42)          |
| `[see @key]`      | (see Author Year)             |
| `[@key1; @key2]`  | (Author1 Year1; Author2 Year2)|
| `@key`            | Author (Year) — narrative form|

Pandoc's [citation syntax docs](https://pandoc.org/MANUAL.html#citations) covers the full grammar.

## Cite-keys: Better BibTeX convention

Cite-keys follow Better BibTeX defaults: `<firstauthor-lastname><year><veryshorttitle>`, all lowercase ASCII, alphanumeric only, no separators.

| Source                                                                      | Key                          |
|-----------------------------------------------------------------------------|------------------------------|
| Arnold (1995), "Remarks on eigenvalues..."                                  | `arnold1995remarks`          |
| Bik & Draisma (2020), "An Euclidean distance degree formula..."             | `bik2020euclidean`           |
| van der Waerden (1927), "Beweis einer Baudetschen Vermutung"                | `vanderwaerden1927beweis`    |
| Knuth (1984), "The TeXbook"                                                 | `knuth1984texbook`           |

Rules:

- **Lastname**: first author only, lowercased ASCII.
  Compound lastnames (`van der Waerden`) keep all parts joined with no separator.
- **Year**: 4-digit publication year.
- **Veryshorttitle**: first significant word of the title (skipping articles, prepositions, conjunctions), truncated to ~12 characters.
- **Collisions**: append `a`, `b`, `c`, ... when two keys would otherwise match.

`cite-tool generate` enforces uniqueness and warns on collisions.

## Reference types

Use BibTeX/biblatex types.
The most common across research domains:

| `type:`         | When to use                                                  |
|-----------------|--------------------------------------------------------------|
| `article`       | Journal article                                              |
| `book`          | Book                                                         |
| `incollection`  | Chapter in an edited collection                              |
| `inproceedings` | Conference paper                                             |
| `unpublished`   | Manuscript, preprint without venue                           |
| `online`        | Web page, blog post                                          |
| `software`      | Software / code                                              |
| `dataset`       | Research dataset                                             |
| `thesis`        | Thesis (use `phdthesis` / `mastersthesis` for specificity)   |
| `report` / `techreport` | Reports                                              |
| `misc`          | When nothing else fits                                       |

If you omit `type:`, the loader infers one (`journal:` present → `article`; `booktitle:` → `inproceedings`; otherwise → `misc`) and warns.

## Common fields

| Field          | Notes                                                          |
|----------------|----------------------------------------------------------------|
| `key`          | The cite-key (required)                                        |
| `type`         | BibTeX type (required; will warn + infer if missing)           |
| `authors`      | List of strings; either "Lastname, Firstname" or "F Lastname"  |
| `editors`      | List of strings (same form)                                    |
| `title`        | The work's title                                               |
| `year`         | Publication year                                               |
| `journal`      | For `article`                                                  |
| `booktitle`    | For `incollection`, `inproceedings`                            |
| `volume`, `number`, `pages` | Standard BibTeX                                  |
| `publisher`, `address`      | For books                                        |
| `doi`          | Digital Object Identifier (no `https://doi.org/` prefix needed)|
| `url`          | Web URL                                                        |
| `eprint` + `eprinttype` | For arXiv: `eprint: "2501.12345", eprinttype: arxiv`  |

Anything not in the recognized field set is passed through to the bib as a non-standard field with a warning.

### A note on `authors`

YAML's flow-sequence treats commas as item separators.
So this is a trap:

```yaml
# WRONG — parsed as 6 separate items
authors: [Almeida, Paulo Sérgio, Shoker, Ali, Baquero, Carlos]
```

Always quote names or use block form:

```yaml
# Correct — flow with quoting
authors: ["Almeida, Paulo Sérgio", "Shoker, Ali", "Baquero, Carlos"]

# Correct — block form
authors:
  - "Almeida, Paulo Sérgio"
  - "Shoker, Ali"
  - "Baquero, Carlos"
```

Names in either order — `Lastname, Firstname` or `Firstname Lastname` — work; the bib renderer normalizes to the BibTeX-canonical comma form.

## Optional: `references/` directory for research notes

A domain *can* have a `references/<key>.md` file when you want to keep prose research notes about a cited source — what it argues, what's reusable, where it sits in the literature.
This is purely optional and unrelated to the bib: the directory can be deleted with no loss for any cited key.
Citations resolve from frontmatter alone.

If frontmatter on a `references/<key>.md` file happens to carry citation metadata fields (authors, year, title), those get folded into the bib for fields the inline declarations didn't carry — never overriding, only filling in.
But the inline declaration is the source of truth.
