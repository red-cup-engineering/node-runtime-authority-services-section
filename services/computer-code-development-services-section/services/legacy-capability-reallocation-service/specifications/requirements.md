# Legacy capability retirement

An explicit `sourceLegacyRoot` MAY name an upstream relocation independently of
the immutable native review cut and any staged local `workingLegacyRoot`.
Validate the confined legacy root, qualify every mapped upstream mode/type/blob
before local effects, and publish only that mapped cut through the same maker.
Preserve native review and commit paths and unrelated local staging. Retain the
source mapping in results, preparation and batch snapshots; refuse mixed source
mappings and changes to a retained operation. Unknown or edited mapped preimages
MUST refuse before deletion. Do not infer a relocation from a filename match.

The Leader's 2026-10-23 request is to revive information in
`lib/emsenn/services/561-group/lib/legacy` into living services. Review a
folder's capabilities briefly, find their living owners even when names,
package boundaries or repository mounts are malformed, and remove covered
legacy files. Lean material is explicitly deprecated. Git history supplies
recovery, not evidence of a replacement capability.

The same originating instruction says: "For each code thing, we need to assume
it has a proper home, that home likely has better code, but is in some ways
non-conformant, i.e. not its own repo, malformed package name, other issues."
Review shall therefore compare folder-level capabilities and actual living
owner responsibilities, rather than require endpoint-by-endpoint or test-by-test
equivalence. Once that capability home is evidenced, unfinished owner conformance
or an unverified historical detail alone shall not retain a duplicate legacy
implementation. State the authorized assumption and unverified properties in the
retirement reason; do not claim those properties are implemented or installed.
Meaningful unique information and genuinely missing capabilities still require
integration. Exact Git preimages, selected-path commits and independent source
and canonical-record receiving remain mandatory.

The service shall inventory an explicitly selected committed subtree without
walking the host or reading every source body. It shall retain exact Git
revision, path, object identity and executable/symlink modes. A retirement
shall name a capability, reason, exact selected source paths and either a
living implementation witness or explicit deprecation authority. Unknown
capabilities and meaningful unique information remain for integration.

Deletion shall affect only selected committed files whose index and working
bytes/modes still match that revision. Untracked files, local edits, Gitlinks
and paths reached through symlinks shall survive. Independent eligible files
shall proceed when another is held. The ordinary CLI shall support preview,
apply, and repeated receiving without recursive directory deletion.

Applying through the ordinary command shall commit that batch's exact removals
before returning. It shall preserve unrelated staged work and handle literal
Unicode, newline and glob characters in filenames. A failed commit shall be
reported as uncommitted with a failing exit status; another batch shall not
begin until that retirement is landed. Leader, 2026-10-23: "because you ddin't
commit your retirement, another agent restored it as possibly a glitch".

Acceptance: use this on the actual legacy collection; compare against the

Test a covered capability, an explicitly deprecated one, Unicode/newline

The preexisting `retire-wave` v2 reconciles into mounted living owners and

A named result destination with a missing/unwritable parent or an existing
non-file target shall be refused before source deletion or Git landing. A
caller must not discover an unusable receipt path only after the retirement
has committed. This requirement follows the actual 2026-10-24 receiving job,
whose four-file commit succeeded before its nonexistent output parent failed.

The ordinary retirement command shall optionally finish upstream source
publication in the same invocation. It shall pass only the reviewed cut to
the existing Fabrication maker, refuse stale reviewed preimages, and receive
the actual immutable merge. It shall preserve the local commit and any
completed external effect when receiving fails. Repeating the same request
and durable output shall reconcile the original publication without another
push or review. A local-only invocation remains available.

Before a new `--apply --publish` retirement removes or commits any source,
the service MUST qualify the selected original mode/type/blob preimages at an
actual advertised original remote commit. The accepted local immutable plan
cut need not itself exist at that remote. Retain both the reviewed plan cut
and the independently received remote source lease; never substitute local
HEAD for remote source identity. If remote observation, acquisition or any
selected preimage check fails, refuse before deletion or commit. Local-only
apply shall not require an origin or remote availability. A retained source
candidate or completed merge shall continue its original receiving path on
replay, without preparing a replacement candidate or push.

The same command shall optionally publish the retirement's plan, completed
result and explicitly selected supporting records through the existing maker.
The caller supplies their actual repository and the maker's reviewed-path
request; this service shall not implement another source publisher. Validate
that declaration and both receipt destinations before retiring source.
Keep the record-publication receipt outside its own publication cut, so its
merge identity never makes the published retirement result self-referential.
After a record publication retains an interrupted candidate, replay shall receive the original
candidate without rewriting the completed retirement result, recommitting
deletions or opening another review. Changed record bytes, a substituted owner
or a different path set shall stop that replay before any effects.

Batch preparation shall belong to this same command. Given explicitly reviewed
canonical plans, explicitly named supporting JSON records and exact output
custody, it shall assemble one canonical plan, an exact-input snapshot and a
complete existing-maker record request. Only plans with the same source owner,
legacy subtree and immutable revision may combine. Duplicate capability IDs,
overlapping source paths, changed evidence, absent deprecation authority and

record outputs, omitted preimages MUST be observed from the actual origin/main
through the existing source reader before any generated-file write or retirement
effect. All three destinations MUST be absent at that immutable remote cut.
Persist the lease in the generated request and reuse it unchanged on partial,
interrupted and completed replay; never replace it with a new remote observation.
Unreachable origin or an occupied destination MUST leave source and outputs

capability judgment, authority, source publisher or installed-use claim.

Preserve original UTF-8 input bytes, their hashes and direct living-code
witnesses. Only explicitly snapshotted record witnesses may be replaced by

Preparation and replay must be deterministic, bounded and restartable without

Completed retirement and record publications MUST remain reobservable when an

A transient read-only receiving failure MUST preserve the last completed

Before any first source-publishing retirement deletion or commit, the service
MUST admit the complete selected-path request and its exact remote source lease
through the selected canonical Git Source Reading request decoder. Supplier
request refusal MUST leave local originals and Git state untouched. Preserve
literal admitted Git filename bytes; do not rewrite paths to make them admissible.
Retained candidate replay keeps its original immutable publication identity.

A reviewed plan MAY declare a different `workingLegacyRoot` when an unchanged
legacy subtree has been moved in the Git index but that relocation is not yet
committed. The original immutable source cut and remote publication paths MUST
remain unchanged. Before removing a moved file, verify that its original path is
absent from both working tree and index, its original HEAD entry still equals
the reviewed source, and its moved index entry and working bytes/mode match.
The moved path MUST NOT already exist in HEAD. Changed or recreated originals,
changed moved files/index entries and overlapping roots MUST refuse removal.

Retirement MUST remove the selected moved additions from the index before
committing their original-path deletions, so a later relocation commit cannot
restore retired files. Preserve every unrelated staged relocation and edit.
Recheck the moved cut before committing, detect recreation after committing,
and allow replay only when both original and moved copies remain absent.
Batch composition MUST retain this local mapping and refuse mixed mappings.

## Selected-source owner discovery

Owner discovery shall also consume explicitly selected source members from
existing pinned-Git or published-owner receiving records. It shall not require
copies of living code or another native checkout. Read each named receipt once,
within the combined byte budget, and retain its SHA-256 and exact selected member
provenance. Verify text length/hash, Git blob identity or archive member identity,
and the original review-only status. Refuse ambiguous selections, altered bodies,
credentials in source locators, linked records and exceeded bounds. Preserve
unknown sources and the existing direct-export hint semantics; receipt claims
are evidence for review, never semantic coverage or deletion authorization.

The service shall compare explicitly selected immutable Git source files with
explicitly named living source modules without walking either directory tree.
It shall reuse the existing source-signal reader and committed-subtree inventory,
retain original blob/mode and SHA-256 identities, and report every observed owner
once with indexed candidate links. A shared symbol is a discovery hint, never a
coverage verdict or retirement authority. Sources without a match remain visible.

The read shall refuse mutable revisions, unknown or repeated selections, legacy
or linked owner paths, nonregular owner files, and exceeded per-file or combined
byte limits. It shall read committed bytes even when native source is edited or
already retired. It shall perform no import evaluation, network request, index
change or deletion. Literal source filenames shall remain unchanged.

A named owner may have a proper repository without a native checkout. Receive its explicitly selected textual files through the existing pinned Git source reader, at an exact immutable commit, without checkout, import evaluation, lifecycle execution or gitlink traversal. Validate all requests before acquisition. Bound owner count, paths, tree metadata and individual/aggregate bytes. Refuse missing, duplicate, non-regular, incorrectly attributed, invalid UTF-8 or object-mismatched files. Retain the actual Git identity, executable mode, text and SHA-256 of every file. Credentials belong only to the transient reader environment; evidence grants no retirement or runtime authority. Dispose only the reader's own scratch after all readers stop, including failed receiving. The ordinary CLI must produce an exclusive new JSON evidence record suitable for the existing retirement batch's supportingRecords.
